How to read this

How to read these checks.

157/157 is Hive’s local automated test result. It is not a feature-parity grade, model score, or proof that external services are online. Competitor entries are based on public product documentation, not hands-on installs or accounts.

What exactly did Hive’s test run cover?+

Three local suites ran successfully: 116 Tier 1–4 feature, boundary, interaction and scenario checks; 31 Node feature tests; and 10 Tier 5 adversarial checks. Areas include search and citations, entitlement gates, feedback, quota/RPC wiring, chat history, group bot discussion, user skills, voice transcript filtering and playback completion/error paths. These tests exercise local code and mocks. They do not prove provider uptime, real microphone permissions or a successful authenticated Supabase session.

Why is Hive voice shown as partial?+

Voice behavior has automated local checks, but access is gated by an explicit account grant. In the current Hive source, the voice widgets and voice mode selector are hidden by feature flags. A passing playback test does not mean every user can open voice in the live app.

What is still unverified?+

Live Supabase sign-in, row-level security and authenticated RPC responses. Real provider and integration credentials and service uptime. Hands-on competitor workflows in Grok Bot, ChatGPT Dots and OpenMausBot. Those are intentionally labeled unverified rather than counted as passes.
